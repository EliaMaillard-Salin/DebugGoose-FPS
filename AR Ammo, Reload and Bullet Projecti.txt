AR Ammo, Reload and Bullet Projectile
Add ammo, reload and a real bullet to the BP_AR gun. This assumes the gun already fires with StartFire and StopFire.
Before you start
• Have BP_AR (the gun) and BP_TestPlayer (the cube character) working, with the gun firing when you hold the left mouse button.
• Compile and save after every part (Compile button, then Ctrl+S). Test after every part. If something breaks, you will know which part caused it.
• Right-click in the empty grid of a graph to search for nodes. Dragging a wire from a pin and letting go in empty space does the same search, and connects the new node automatically.
• A blue, red or green dot on a node is a pin. White arrows are the execution flow (the order things happen). Coloured pins carry values.
Part 1: Create the ammo variables (in BP_AR)
1. In the Content Browser, double-click BP_AR to open it. Click the Event Graph tab at the top.
2. In the My Blueprint panel on the left, find Variables and click the + next to it. A new variable appears. Type the name MaxAmmo and press Enter.
3. With MaxAmmo selected, look at the Details panel on the right. Next to Variable Type, click the dropdown and choose Integer (a whole number).
4. Click Compile at the top. Now the Details panel shows a Default Value box. Type 30 there.
5. Repeat for the other three variables:
    ◦ CurrentAmmo: type Integer, default value 30
    ◦ ReloadTime: type Float, default value 2.0 (seconds)
    ◦ bIsReloading: type Boolean, default value left unticked (off)
6. Compile again. You should now see four new variables in the My Blueprint panel.


Part 2: Build the Reload event (in BP_AR)
Build this before you change Fire, because Fire will call it.
1. Right-click an empty area of the Event Graph, type Add Custom Event, and click it. Name it Reload and press Enter. A red event node appears.
2. Drag from the white arrow on Reload to empty space, type Branch, and click Branch.
3. Build the condition (this stops reloading when the gun is already full or already reloading):
    ◦ Drag bIsReloading from the My Blueprint panel into the graph and choose Get. Drag from its output pin, type NOT, and choose NOT Boolean.
    ◦ Drag CurrentAmmo into the graph and choose Get. Drag from its output pin, type <, and choose the Integer < Integer version. Drag MaxAmmo into the graph (Get) and connect it to the second pin of the < node.
    ◦ Drag from the output of the < node, type AND, and choose AND Boolean. Connect the NOT node's output to the second input of the AND node.
    ◦ Connect the AND node's output to the Condition pin of the Branch.
4. From the Branch's True arrow, add Set bIsReloading: drag bIsReloading into the graph, choose Set, connect it, and tick its checkbox (this sets it to true).
5. After that, call StopFire: drag from the Set node's white arrow, type StopFire, and click it. This stops the gun mid-reload.
6. After that, add a Delay: drag from the white arrow, type Delay, and click Delay. Drag ReloadTime into the graph (Get) and connect it to the Duration pin.
7. Connect the Delay's Completed arrow to a new Set CurrentAmmo (drag CurrentAmmo into the graph, choose Set). Drag MaxAmmo into the graph (Get) and connect it to the value pin on that Set node.
8. After that, add another Set bIsReloading, this time with the checkbox unticked (false).
9. Leave the Branch's False arrow empty on purpose.
10. Optional for testing: after the last Set, add a Print String with the text Reloaded.
11. Compile.
Delay only works in the Event Graph, not inside a function, so keep all of this in the Event Graph.


Part 3: Limit Fire by ammo (in BP_AR)
Your Fire event currently goes straight into Line Trace By Channel. We will put a Branch in between.
1. Find the red Fire custom event. Drag from its white arrow to empty space, type Branch, and click it. It replaces the old link, so the Line Trace is now disconnected for a moment.
2. Build the condition CurrentAmmo > 0 AND NOT bIsReloading:
    ◦ Drag CurrentAmmo into the graph (Get). Drag from its pin, type >, and choose the Integer > Integer version. Type 0 in the second box.
    ◦ Drag bIsReloading into the graph (Get), then drag from its pin and choose NOT Boolean.
    ◦ Drag from the > output, choose AND Boolean, and connect the NOT output to its second input.
    ◦ Connect the AND output to the Branch Condition.
3. Connect the Branch True arrow to the white input of Line Trace By Channel (your existing node and all its wires stay as they are).
4. After the Line Trace, subtract one bullet per shot: drag from the Line Trace's white output arrow, then add Set CurrentAmmo (drag CurrentAmmo into the graph and choose Set). Drag CurrentAmmo into the graph again (Get), drag from its pin, type -, choose Integer - Integer, type 1 in the second box, and connect the result to the value pin of the Set node.
5. Optional for testing: after that Set, add a Print String and connect CurrentAmmo (Get) to its text pin. You will see the count go down on screen.
6. From the Branch False arrow, add a call to StopFire (drag from the arrow, type StopFire). Then drag from its white arrow, type Reload, and click the Reload event call. This makes an empty gun reload by itself.
7. Compile and save.


Part 4: Add the R key (in BP_TestPlayer)
1. Open BP_TestPlayer and go to its Event Graph.
2. Right-click empty space, type R, and choose the R keyboard event (under Input, Keyboard Events).
3. Reuse the same setup you used for the mouse button: Get Child Actor (from the ChildActor component) into Cast To BP_AR. If you do not have one nearby, drag ChildActor from the Components panel into the graph, drag from its pin, and search Get Child Actor, then drag from the output and search Cast To BP_AR.
4. Connect Pressed on the R event to the white input of the cast.
5. Drag from the cast's As BP AR pin, type Reload, and click the Reload call. Its arrow connects from the cast's white output.
6. Compile and save.


Part 5: Test ammo and reload
1. Press Play. Hold the left mouse button.
2. Watch the top-left of the screen: the numbers should count 29, 28, 27 and so on.
3. At 0 the gun should stop, wait 2 seconds, and then you can fire again. You must release and press the mouse button again after a reload, because reloading stops the fire timer.
4. Fire a few shots, then press R. The gun should refill to 30 after 2 seconds. Press R again while it is already full or reloading: nothing should happen.
Do not move on until this works.


Part 6: Create the bullet (BP_Bullet)
1. In the Content Browser, right-click, choose Blueprint Class, then Actor. Name it BP_Bullet and double-click it to open.
2. In the Components panel, click Add, search Sphere Collision, and click it. Drag it on top of DefaultSceneRoot so it becomes the root.
3. With the sphere selected, in Details set Sphere Radius to 6. Under Collision, tick Simulation Generates Hit Events, and set Collision Presets to BlockAllDynamic.
4. Add a visible shape: click Add, search Static Mesh, add it as a child of the sphere (drop it on the sphere). In Details choose the Mesh Sphere, set Scale to 0.1, 0.1, 0.1, and set its Collision Presets to NoCollision.
5. Click Add, search Projectile Movement, and add Projectile Movement Component. Select it and set Initial Speed to 8000, Max Speed to 8000, Projectile Gravity Scale to 0 (straight flight, or 0.2 for a slight drop), and tick Rotation Follows Velocity.
6. Click Class Defaults at the top and set Initial Life Span to 3. Bullets that miss will delete themselves after 3 seconds.
7. Compile and save.


Part 7: What happens when the bullet hits (BP_Bullet)
1. In the Components panel click the Sphere component. Scroll down in the Details panel to the Events section and click the green + next to On Component Hit. An event node appears in the Event Graph.
2. Drag from its white arrow, type Apply Damage, and click Apply Damage. Connect the event's Other Actor pin to Damaged Actor, and type 20 into Base Damage.
3. Drag from the Apply Damage white arrow, type Destroy Actor, and click Destroy Actor. Leave its Target as self.
4. Compile and save.
Nothing in your game has a health value yet, so the damage does nothing for now. It is ready for when you add health.


Part 8: Spawn the bullet from Fire (in BP_AR)
We keep the line trace to find where the crosshair points, and the bullet flies from the muzzle to that point.
1. In BP_AR, click the Gun component. In Details, set Collision Presets to NoCollision so the bullet cannot hit the gun itself.
2. Open the Event Graph. Find your Line Trace By Channel node. Between it and Set CurrentAmmo, we will add the spawn. Drag from the Line Trace's white output arrow, type Spawn Actor from Class, and click it. Set Class to BP_Bullet. Reconnect the spawn node's white arrow to Set CurrentAmmo.
3. Change Collision Handling Override on that node (click the small arrow at the bottom of the node to show it) to Always Spawn, Ignore Collisions.
4. Work out the aim point. Right-click, type Select, and add the Select node (the wildcard one). Connect the Line Trace Return Value (the red bool pin) to Pick A. From the Line Trace Out Hit pin, drag and add Break Hit Result, then connect its Impact Point to the A pin of Select. Connect the same value you used for the Line Trace End pin (the output of your + node) to the B pin. This means: if the trace hit something, aim there; otherwise aim at the far end of the line.
5. Find the direction: right-click, type Find Look at Rotation, and click it. Connect the Select output to Target. For Start, drag the Muzzle component from the Components panel into the graph, drag from its pin, type Get World Location, and connect the output to Start.
6. Build the spawn position slightly in front of the muzzle so the bullet does not start inside the cube. Drag from the Return Value of Find Look at Rotation, type Get Forward Vector, and click it. Drag from its output, choose Vector * Float, and type 100. Then add a Vector + Vector node: connect the Muzzle's Get World Location to one input and the multiplied result to the other.
7. Right-click, type Make Transform, and click it. Connect the + result to Location and the Find Look at Rotation Return Value to Rotation. Leave Scale at 1, 1, 1. Connect the Make Transform output to the Spawn Transform pin of the spawn node.
8. Optional: once the bullets look right, set the Line Trace Draw Debug Type back to None.
9. Compile and save both Blueprints.


Part 9: Test the bullet
1. In the level, drag a large cube or wall in front of the player (Place Actors panel, Shapes, Cube) so the bullets have something to hit.
2. Press Play and hold the left mouse button. You should see small spheres flying from the gun to the crosshair and disappearing when they hit the cube.
3. Reload (R) and the ammo count should still work as before.
If something goes wrong
• No bullets appear: check that the Spawn Actor Class is BP_Bullet, that the spawn node's white arrow is connected, and that the bullet has the little sphere mesh from Part 6, step 4.
• Bullets vanish right away: the bullet is hitting the player or the gun. Check the Gun collision is NoCollision, and change the 100 in Part 8, step 6 to 150.
• Bullets go the wrong way: check that the Find Look at Rotation Start is the muzzle location and Target is the Select output.
• Bullets are too slow or too fast: change Initial Speed and Max Speed together in BP_Bullet.
• Gun does not stop at 0: check the Branch condition in Part 3 and that the > node has 0 typed in.
• Reload does nothing: check that Reload has a Branch with the condition from Part 2, and that you compiled BP_AR before searching for Reload in the character.
• StartFire, StopFire or Reload do not show in the node search: compile BP_AR first.
